# WB-002: Рассылка уведомлений нескольким получателям

## Что происходит

Бот отправляет уведомления ровно в один чат. Идентификатор получателя задан
переменной окружения RESETWATCH_BOT_CHAT_ID, в ней стоит чат пользователя.
Коллега пользователя уведомлений не получает вовсе, сообщения доходят до неё
пересылкой руками. Telegram вдобавок запрещает боту писать человеку, который
не начинал диалог. Без нажатия коллегой Start добавить получателя нельзя
даже кодом.

## Чего хотим

Notify.Send обходит список получателей вместо одного. Список лежит в
переменной окружения через запятую, пустые элементы выкидываются. Старая
переменная с единственным чатом продолжает работать. Сбой доставки одному
адресату не отменяет остальных. Неудача пишется в журнал с идентификатором
чата и кодом ответа. Идентификатор чата коллеги собирается однократным
вызовом getUpdates после её Start. Постоянный приём апдейтов боту не нужен.

- выкат на машину алертов, живое уведомление коллеге после её Start

## Ранг

`0+6+0+0+1 = 7`, P3 (бонус S+2, итог 9).

- Серьёзность 0: уведомления ходят, пользователь обходится пересылкой.
- Ценность 6: рассылку ждёт второй человек, сейчас у него нет ничего.
- Неопределённость 0: механика известна, развилок нет.
- Рычаг 1: список получателей снимает ручную пересылку будущих событий.

## Приёмка

- вид: user
- барьер «глаза»: итог это пришедшее уведомление в живом чате Telegram, сверять его можно только глядя в экран телефона
  - утверждённый макет: не годится, макета чата Telegram нет и утверждать его ради одной строки уведомления не стоит
  - headless-браузер с замером: не годится, Telegram-чат не веб-страница, замерять нечего
  - тест по разметке и стилям: годится для разбора списка получателей и продолжения рассылки, но живую доставку в чужой чат не доказывает

## Сценарий проверки

После выката на машину алертов.

- Исключение: обкатка (все шаги идут в живом окружении машины алертов: токен
  бота, Start от коллеги, правка resetwatch.env и рестарт systemd). В свежем
  локальном дереве исполнять нечего, шаги проверяются живой приёмкой.


1. Коллега находит бота в Telegram и нажимает Start, иначе бот не может
   писать ей.
2. Я однократно вызываю getUpdates на машине алертов, чтобы забрать её
   chat id:

       curl -s "https://api.telegram.org/bot$RESETWATCH_BOT_TOKEN/getUpdates" | jq '.result[-1].message.chat.id'

3. Правлю /opt/resetwatch/resetwatch.env: вместо RESETWATCH_BOT_CHAT_ID
   ставлю RESETWATCH_BOT_CHAT_IDS со своим чатом и её чатом через запятую.
4. Рестартую сервис: systemctl restart resetwatch.
5. Довожу до события (или жду ближайшего) и смотрю в оба телефона: уведомление
   приходит и мне, и коллеге.
