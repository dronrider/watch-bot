# WB-002: Рассылка уведомлений нескольким получателям

## Что происходит

Бот отправляет уведомления ровно в один чат. Идентификатор получателя задан
переменной окружения RESETWATCH_BOT_CHAT_ID, в ней стоит чат пользователя.
Коллега пользователя уведомлений не получает вовсе, сообщения доходят до неё
пересылкой руками. Telegram вдобавок запрещает боту писать человеку, который
не начинал диалог. Без нажатия коллегой Start добавить получателя нельзя
даже кодом.

## Чего хотим

Notify.Send обходит список получателей вместо одного. Список лежит в
переменной окружения через запятую, пустые элементы выкидываются. Старая
переменная с единственным чатом продолжает работать. Сбой доставки одному
адресату не отменяет остальных. Неудача пишется в журнал с идентификатором
чата и кодом ответа. Идентификатор чата коллеги собирается однократным
вызовом getUpdates после её Start. Постоянный приём апдейтов боту не нужен.

## DoD

- переменная окружения держит список получателей, каждому уходит своя копия
  сообщения
- сбой одного адресата не роняет рассылку остальным и виден в журнале
- выкат на машину алертов, живое уведомление коллеге после её Start

## Ранг

`0+6+0+0+1 = 7`, P3.

- Серьёзность 0: уведомления ходят, пользователь обходится пересылкой.
- Ценность 6: рассылку ждёт второй человек, сейчас у него нет ничего.
- Неопределённость 0: механика известна, развилок нет.
- Поправка на баг 0: это новая работа, ничего не сломалось.
- Рычаг 1: список получателей снимает ручную пересылку будущих событий.

## Приёмка

- вид: user
- барьер «глаза»: уведомление видно глазами в чате коллеги, шаги проверки прикладываются при переводе в Check
