# watch-bot

Правила работы живут в devkit рядом с проектом (`../devkit`). Ядро для любой
сессии это `RULES.md`, для проектов с доской добавляется `RULES.board.md`.
Если ссылки в файле харнеса не развернулись, devkit не склонирован. До любой
работы с кодом и текстами оба файла читаются явно.

## Задачи

Доска `docs/TASKS.md`, префикс `WB`. Механику доски гоняет taskctl, таблицы
руками не править.

## Проект

Монитор сбросов лимитов Codex и Claude. Го-хост опрашивает источники по
расписанию, адаптеры на JS под goja собирают события, Telegram-бот присылает
новые. Состояние лежит в SQLite. Дедуп двойной. Внутри источника события
различаются идентификатором, между источниками ссылкой на пост.

Сборка и тесты требуют GOWORK=off, go.work машины перекрывает модуль. Тесты
гонятся обёрткой `devkitctl test <каталог проекта>`. Выкат это статичный
linux-бинарь, конфиг и адаптеры на машине алертов, затем рестарт сервиса.

Развёрнутая карта компонентов в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md),
стиль в [docs/STYLEGUIDE.md](docs/STYLEGUIDE.md). Выкат живёт в гитигнорнутом
`.devkit/deploy.local`, откуда его берёт `shipctl merge`. Флаг
`autonomous = true` там же отдаёт агенту весь конвейер, от слияния до выката
(RULES.board.md, «Ветки, ревью и деплой» п. 8).
